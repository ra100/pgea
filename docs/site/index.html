a small Postgres proxy / no. 001

Your Postgres client, talking to private-VPC Aurora.

pgea listens on localhost as a Postgres server, then forwards every query to the AWS RDS Data API. If your Aurora cluster has no public endpoint and you don't want to keep a bastion or VPN running just to poke at it, that's the gap this fills.

i.

What's inside

  1. 01

    Speaks Postgres wire

    Simple and Extended query, transactions, $N parameter rewriting, prepared statements, portals. Anything your client already knows how to send.

  2. 02

    RDS Data API on the back

    Queries turn into ExecuteStatement calls. BEGIN / COMMIT / ROLLBACK map to the matching transaction calls.

  3. 03

    Plays nicely with GUIs

    The Data API refuses some catalog queries DBeaver and DataGrip rely on. pgea rewrites those specific ones so introspection still works.

  4. 04

    Reuses your AWS setup

    Credentials come from the standard chain: AWS_PROFILE, env, SSO, IMDS. The pg password field becomes a per-connection profile override.

  5. 05

    Many clusters, one proxy

    Each cluster is a named target in ~/.config/pgea/config.toml. Pick one by setting dbname in your client.

  6. 06

    Doesn't fail loudly

    Credentials resolve on the first connection to a target, not at startup. A stale SSO session for one cluster won't stop you from using another.

ii.

Install

Prebuilt binaries for macOS arm64 and Linux x86_64. The script drops pgea into $HOME/.local/bin:

curl -fsSL https://raw.githubusercontent.com/ra100/pgea/main/install.sh | bash

If you want a specific version, pass it in:

PGEA_VERSION=v0.1.1 curl -fsSL https://raw.githubusercontent.com/ra100/pgea/main/install.sh | bash

Or build from source if you'd rather not run a curl-bash:

cargo install --git https://github.com/ra100/pgea

Updating later is just:

pgea self-update
iii.

Configure

Put a TOML file at ~/.config/pgea/config.toml. One [targets.NAME] block per Aurora cluster:

listen          = "127.0.0.1:15000"
default_profile = "default"

[targets.playground_uat]
profile     = "uat"
region      = "us-east-1"
cluster_arn = "arn:aws:rds:us-east-1:123456789012:cluster:my-cluster"
secret_arn  = "arn:aws:secretsmanager:us-east-1:123456789012:secret:my-cluster-credentials-XXXXXX"
database    = "appdb"

Then start it:

pgea --config ~/.config/pgea/config.toml

Connect with any Postgres client. The dbname picks which target you hit. The password field, if you set it, overrides the AWS profile for that connection.

iv.

Status

Early. v1 handles connection routing, Simple and Extended Query, transactions, and the few catalog rewrites GUIs need to introspect a database.

What it doesn't do yet

  • COPY, server-side cursors, LISTEN / NOTIFY, SAVEPOINT.
  • Multi-statement Simple Query.
  • Pagination around the Data API's 1 MB result cap. Big result sets get truncated.
  • TLS between the client and pgea. It only listens on 127.0.0.1.
  • Caching prepared statements across sessions.

The design spec has the full scope and the reasoning behind what's in v1 and what isn't.
